## Ошибки прежней реализации, которые исправлены

1. Новый центральный хост не создаём: подписывающие функции должны
   выполняться в изолированном root-only процессе **на 188**.
2. Прокси для пользователя — **Telegram MTProxy/Telemt**, не Nginx
   `ssl_preread`. Nginx SNI маршрутизатор в FI-кандидате принадлежит
   только Smart DNS. Поэтому `nodekit/service_readiness.py` отдельно
   выдаёт `dns_sni_transport` и **неподтверждённый** `telegram_proxy`.
3. Приватный подписывающий ключ контроллера должен открываться через
   защищённый файловый дескриптор без symlink/path-swap; фиксировано в
   `grunvald91/Mnebyvpn/apps/service/src/awg-controller-delivery-worker.ts`.

## Особые границы

- Существующий Telegram-прокси на 89 нельзя переустановить ради FI.
  Исторический путь `188:8443 → WG → 89:443 → direct-ozon`
  требует **отдельного** мобильного E2E-теста и отзыва персонального секрета.
- Нельзя создавать публичную общую DNS-ссылку или Telemt-секрет без
  привязки к конкретной подписке.
- Проброс локального Telemt API из 89 в 188 без проверки SSH/TLS
  и разрешённых команд недопустим; API не выставлять напрямую в интернет.
- Любой запуск с правом подписи grant должен использовать текущую
  каноническую БД, подписанный ack и проверяемый срок, а не обходить
  биллинг или автоматически публиковать FI.
- Действующие 188/89 узлы и выданные ссылки должны оставаться неизменными
  до сквозной проверки canary.

Одноразовый безопасный аудит фактического runtime: 
[controller188-fi-telemt-gaps-readonly.yml](../.github/workflows/controller188-fi-telemt-gaps-readonly.yml).
Он не пытается читать ключи, подписывать команды или создавать клиентов.
