# MNEBYVPN — завершение подключения поддержки

Код сайта и основного Telegram-бота развёрнут на VPS через существующие проверенные workflows. Для исходящих обращений оператору нужно **один раз** внести тот же BotFather API token основного `@MnebyVPN_bot` в защищённый GitHub Actions secret именно этого инфраструктурного репозитория.

## Однократная настройка

1. Откройте [Secrets and variables → Actions](https://github.com/grunvald91/telegram-proxy-infra/settings/secrets/actions) в `grunvald91/telegram-proxy-infra`.
2. Создайте **Repository secret** с именем `MNEBYVPN_SUPPORT_BOT_TOKEN`. Значение — настоящий Bot API token `@MnebyVPN_bot`; **не присылайте его в чат и не коммитьте в Git**. Уже существующий токен хранится в секретах другого репозитория и не может быть прочитан из GitHub.
3. Запустите вручную workflow [MNEBYVPN activate support using configured existing bot token](https://github.com/grunvald91/telegram-proxy-infra/actions/workflows/mnebyvpn-support-activate.yml) → **Run workflow** → `main`.

Операторский ID уже подготовлен в **зашифрованном** файле `ops/secure/mnebyvpn-support-owner.enc.b64`. Закрытый RSA ключ находится только на сервере MNEBYVPN; ни отдельный Telegram-чат поддержки, ни повторный ввод ID не требуются.

## Что делает workflow

- Проверяет токен через Telegram Bot API `getMe`: допускается **только** существующий `MnebyVPN_bot`.
- Использует существующий доступ на сервер через `SERVER188_SSH_PASSWORD`; токен передаётся исключительно по защищённому каналу SSH stdin, не записывается в Git и не выводится в Actions логи.
- Расшифровывает ID оператора на сервере, делает резервные копии **только** двух приватных MNEBYVPN env-файлов.
- Добавляет `TELEGRAM_TOKEN_BOT` и `SUPPORT_TELEGRAM_OPERATOR_ID` для действующих `mnebyvpn-bot-info` и `mnebyvpn-public-web`.
- Пересоздаёт **только эти два** контейнера проверенными canary/promote-скриптами; не трогает nginx, VPN-узлы, чужие контейнеры, DNS, firewall и сетевую конфигурацию.
- Проверяет готовность Telegram-бота, `/api/support/status` на сайте и отправляет владельцу **одно** контрольное уведомление от того же бота.
- При ошибке пытается восстановить прежние приватные настройки и пересоздать оба контейнера в прежней конфигурации.

## Условия готовности

Работу поддержки можно считать подтверждённой **только после** завершения workflow со статусом `success` и получения владельцем контрольного сообщения. Затем требуется проверить реальный E2E: обращение клиентом через бота → оператор → ответ клиенту; форма сайта → оператор → ответ посетителю в браузере.

Миграция `0018_website_support_tickets.sql` должна быть применена до активации, коммерческие флаги оплаты этот workflow **не изменяет**. При отсутствии секретного токена workflow не стартует активацию; публичная форма остаётся честно недоступной. Не объявляйте сервис поддержки включённым, пока этих условий нет.
