# MNEBYVPN — включение поддержки без нового Bot API token

Поддержка работает через **тот же** @MnebyVPN_bot, которым пользователь управляет VPN, по существующему защищённому Telegram webhook. Secret `TELEGRAM_TOKEN_BOT` исходного репозитория `grunvald91/Mnebyvpn` **не нужно копировать, дублировать, печатать или заменять**.

## Автоматическое включение на действующем сервере

Workflow [MNEBYVPN activate support through existing Telegram webhook](https://github.com/grunvald91/telegram-proxy-infra/actions/workflows/mnebyvpn-support-activate.yml) выполняется через существующий `SERVER188_SSH_PASSWORD` и только в `/opt/mnebyvpn`.

1. Из `ops/secure/mnebyvpn-support-owner.enc.b64` расшифровывается только личный ID оператора через RSA-OAEP-256; закрытый ключ хранится на VPS.
2. Проверяются идентичность уже развёрнутых сайта и бота, наличие миграции 0018, наличие tokenless webhook кода и актуальных версий.
3. К сайту применяется только миграция `0018_website_support_tickets.sql` в его собственной базе `mnebyvpn_public`. На VPS генерируется случайный `SUPPORT_BRIDGE_SECRET` для HMAC-SHA256 обмена между сайтом и ботом, копия этого секрета сохраняется только в двух приватных файлах окружения вместе с `SUPPORT_TELEGRAM_OPERATOR_ID`. Bot API token не копируется. Далее проверенные bot/web promoters выполняют canary, перезапуск и проверку готовности.
4. При ошибке оба env-файла восстанавливаются и предпринимается откат контейнеров.
5. После успеха сайт принимает заявки без Telegram, оператор просматривает их в том же боте с помощью `/inbox`, отвечает через обычный Reply.

**Telegram-заявки:** сообщение клиента приходит владельцу через ответ исходного webhook, ответ владельца уходит клиенту таким же способом — без исходящего Bot API token.

**Заявки с сайта:** сразу сохраняются в базе сайта; бот читает их через подписанный локальный `GET /api/support/operator-inbox` и сохраняет ответ через подписанный `POST /api/support/operator-reply`. Реальные SQL-запросы выполняет сайт под ролью `mnebyvpn_public`, без прямого доступа бота к его БД. Без исходящего Bot API token сайт не отправляет мгновенное уведомление владельцу: он открывает `/inbox` или «Поддержка» в основном боте. Важно: не выдавать очередь за отправленное Telegram-уведомление.

После запуска проверять `/readyz`, `/api/support/status`, отказ при неподписанном webhook, и полный клиентский E2E вручную. Автодеплой MNEBYVPN не должен менять чужие проекты, общий Nginx или настройки безопасности сервера.

Первичный секрет `TELEGRAM_TOKEN_BOT` остаётся в исходном GitHub-репозитории. **Никаких действий владельца с токеном не требуется.**
