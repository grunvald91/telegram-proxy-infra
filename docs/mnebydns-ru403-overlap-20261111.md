# Проверка новых DNS-маршрутов по итогам полного списка, 2026-11-11

**Не является применённой DNS-конфигурацией.** Источник — [успешная GitHub Actions проверка живой конфигурации RU/DE](https://github.com/grunvald91/telegram-proxy-infra/actions/runs/43020532936). Сопоставлены 109 уникальных имён, у которых при HTTPS GET / один и тот же origin IPv4 даёт РФ 403/451 и DE 2xx/3xx, с исключением ранее подключённых пользователем `chatgpt.com` и `grok.com`.

- **108/109**: существующая база данных показывает `PENDING`, генератор точного CoreDNS + Nginx правила не обнаружил пересечения; это лишь предварительное разрешение на отдельный canary, НЕ подтверждение доступности приложения.
- **1/109**: `sentry.io` — имя обнаружено в конфигурации дополнительного Nginx-прокси; отдельное ревью до любых изменений.
- `chatgpt.com` и `grok.com` — сохранены в первичном CSV результатов HTTP, исключены из этого списочного набора по явному сообщению владельца о готовом Smart DNS.
- Во время проверки неизменны CoreDNS, Nginx, PostgreSQL, VPN, Telegram-прокси. Проверена целостность текущего контрольного снимка.

Файлы: [полная матрица 109](../data/mnebydns-109-live-overlap-20261111.csv), [108 предварительно чистых для дальнейших испытаний](../data/mnebydns-108-canary-review-20261111.txt). Исходные 160 ответов 403/451 — [отдельный CSV](../data/mnebydns-ru-http-403-451-20261111.csv).

**Перед вводом каждого домена:** проверить нужные поддомены приложения, RU→DE public ingress и исходный сертификат, согласованность DNS A/AAAA/CNAME/HTTPS/SVCB, пересечение SNI/wildcard, IPv4 и IPv6, UDP/QUIC, отсутствие воздействия на существующие сервисы. Только затем ставить запись в `APPLY_REQUESTED` по одному домену, дать тесту автоматический откат и подтвердить `ACTIVE` по положительной проверке. Нельзя слепо включать 108 доменов за один выпуск.
