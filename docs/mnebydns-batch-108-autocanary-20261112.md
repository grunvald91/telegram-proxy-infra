# MNEBYDNS: безопасная пакетная активация 108 адресов (2026-11-12)

## Что реализовано

- Входные имена: ровно [108 адресов](../data/mnebydns-108-canary-review-20261111.txt), каждый должен присутствовать в исходном [списке 111 различий HTTP](../data/mnebydns-ru-403-451-de-success-20261111.csv). `chatgpt.com`, `grok.com` и `sentry.io` заведомо исключены.
- Новая изолированная [очередь пакетного применения](../scripts/mnebydns-batch-108-canary-20261112.py) повторно использует существующий `mnebydns-owner-domain-controller-20261110.py`, DNS/SNI рендер и systemd rollback. **По одному имени за один переход**, максимум пять за GitHub Actions run.
- До любого изменения: действующий подтверждённый контрольный снимок CoreDNS и Nginx, отсутствие незавершённых чужих задач и других тестов, свободная память и дисковое место, проверки служб и валидности nginx. Проверка актуальности ответа **того же публичного IP**: DE HTTPS GET / — 2xx/3xx, RU прямой HTTPS GET / — 403/451. Если свойства уже не воспроизводятся, исследовательский адрес помечается `FAILED` с `BATCH_PREFLIGHT_UNVERIFIED` и не активируется.
- Каждому адресу даётся отдельный canary ID, оригинальный SNI/Host, закреплённый проверенный origin IPv4, независимый 60-минутный таймер systemd для восстановления и состояние в PostgreSQL.
- После тестового подключения: **из RU через общедоступный зарубежный сервер** делается HTTPS GET / с проверкой обычного TLS сертификата. Требуется HTTP 2xx/3xx. Проверяются публичный DoT, пять уже поддерживаемых доменов, отсутствие нежелательного изменения исключённых DNS-имён, сервисы и серверные ресурсы. Только после этого контроллер подтверждает стабильный checkpoint, `ACTIVE` и запись origin IP.
- Если отдельный сайт недоступен через проверенный RU→DE HTTPS-маршрут, его canary откатывается, конфигурация и базовый DNS сверяются, а домен получает `FAILED` / `BATCH_CANDIDATE_HTTPS_FAILED`. Очередь продолжает следующий адрес. **Если нарушена общая работа DNS или невозможно подтвердить откат**, формируется `BATCH_INCIDENT_CANARY_ABORT` либо процесс завершается с ошибкой; дальнейшие волны останавливаются. Неопределённое состояние подтверждения **не** скрывается под «успешным откатом».
- Состояния и результаты записываются в журнал GitHub Actions; даже при неуспешном процессе выгружается отдельный JSONL артефакт на 30 дней. Очередь восстанавливается по канонической PostgreSQL БД, поэтому повтор запуска не добавляет ACTIVE-подключения.

## Включение и контроль

- Файл [data/mnebydns-batch-auto-enabled-20261112.txt](../data/mnebydns-batch-auto-enabled-20261112.txt) — отдельный переключатель. `disabled`: планирование и офлайн-тесты, **никаких** периодических изменений. `enabled`: при первом merge переключателя выполняется **один** пробный кандидат, а далее каждые три часа — до трёх кандидатов в одном ограниченном запуске. Следующий запуск только после освобождения уже занятого контроллера.
- [GitHub Actions](../.github/workflows/mnebydns-batch-108-canary-20261112.yml): ручной `workflow_dispatch` поддерживает `plan` (без изменений) либо `deploy` (1–5 точных имён). Ручное испытание с `deploy` может запускаться и при `disabled`; плановый запуск не может.
- В случае сбоя остановить автоматизацию, вернув содержимое переключателя в `disabled`. Нельзя редактировать конфигурацию во время незавершённого canary, обходить защитный mutex или стирать `BATCH_INCIDENT_*` без подтверждённого восстановления.
- Техническая проба GET / **не является проверкой логина, приложения, CDN-зависимостей, QUIC, всех поддоменов или работы на телефоне**. Для рекламных обещаний нужен дополнительный прикладной и клиентский тест.
- Варианты с исходным `HTTP 403/451` и без работающего DE 2xx/3xx **не включены**: это отдельные 49 адресов. Справочные 17 и прочие каталожные имена также не включены.
- IP-смена зарубежного origin после активации не переписывается скрытно: существующий owner-domain health обнаруживает проблемы и сообщает; безопасная автоматическая ротация закреплённых upstream IP остаётся отдельной задачей.
- GitHub schedule запускается без жёсткой гарантии точного времени. Для мгновенного отключения новых изменений достаточно переключателя, для восстановления уже активных маршрутов нужна отдельная штатная процедура точечного удаления.
